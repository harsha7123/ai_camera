What to buy

Three ways to build the same system. Every item is a real product you can order today; prices are approximate US retail checked in November 2026 and move often, so confirm before buying. The budget build is the cheapest because one small AI box serves every camera.

Cameras with a built-in AI chip

You asked to prefer a camera that has its own chip, where we install code and set rules. These are the options that genuinely let you run your own code, against the cheap camera that only has the maker's fixed rules.

Our recommendation

Start with the budget build. Ordinary RTSP cameras at about $55 each plus one Jetson Orin Nano Super box ($249) running this repo gives the full feature set for about $1,000. That is less than two smart cameras.

Add smart cameras where they earn it. Put a Luxonis OAK-1 PoE over the register and the back door (Hybrid build). Its own chip finds people at full frame rate and sends only small metadata, which keeps working even if the box is busy.

Avoid cameras from makers barred from new US authorisations (Hikvision, Dahua and their rebrands) if you are in the US, and any camera that will not give an RTSP stream.

Honest status: the repo reads RTSP streams today. Running on a Jetson is expected to work (Linux, ARM64, ONNX Runtime GPU build) but has not been tested yet. The OAK and Raspberry Pi AI Camera paths need a small detector adapter in services/vision-worker that is not built yet.

How the wiring works

  1. One Cat6 cable per camera, from the camera's ceiling spot back to the office closet. Power over Ethernet (PoE) sends power and video down the same cable, so no electrician is needed at the camera. Keep each run under 100 m (328 ft).
  2. Into an 8-port PoE+ switch in the closet. Six cameras draw about 30–40 W; the switch gives 63 W in total.
  3. Switch → AI box with one short patch cable. This switch carries only cameras and the box: a separate, private camera network (192.168.50.x) with no route to guest Wi-Fi or the POS.
  4. AI box → office router with a $15 USB Ethernet adapter, so managers reach the dashboard and the box can send phone alerts. Cameras never touch the internet.
  5. POS stays on its own network. A connector on the box pulls no-sale, void and refund events from the POS maker's cloud and posts them to the box (no card data).
  6. Switch, box and router on a UPS, so a power blip doesn't blind the cameras or lose a clip.

Addresses and settings to write down

Set each camera's static IP and a strong password on the bench before mounting. Turn audio recording off in every camera's settings. RTSP address for Reolink: rtsp://user:pass@192.168.50.11:554/h264Preview_01_main.

How the data travels, and what the code does at each hop

1 · CameraRecords 25 fps H.264 and streams it over RTSP on the Cat6 cable.
2 · SwitchDelivers about 4 Mbps per camera to the box on the private camera network.
3 · Vision workerTakes 5 frames a second (15 at the register), finds people, tracks them and writes an anonymous observation. No faces are stored.
4 · Core rulesChecks zones, business hours and POS events, then opens an incident and cuts an encrypted 30 s clip from a 2-minute buffer.
5 · AlertShows on the dashboard and, when that rule's alerts are switched on, pings the manager's phone.
6 · ManagerWatches the clip and marks it OK, coach or investigate. The AI flags; people decide.

Every rule starts in SHADOW: recorded for the owner, nobody paged. After a 30–60 day tuning period, switch real alerts on per rule with "alerting_enabled": true.

How the GitHub repo helps

Everything that runs on the box is in harsha7123/ai_camera. You buy the hardware; the repo is the brain.

Install day, in order

  1. Bench-set each camera: update firmware, static IP, strong password, audio off, check the RTSP stream plays in VLC.
  2. Flash JetPack onto the box's NVMe SSD, then git clone https://github.com/harsha7123/ai_camera and install Go, uv, ffmpeg and PostgreSQL.
  3. Pull the Cat6 runs, crimp the ends, test every run with the tester, then mount the cameras.
  4. Copy services/core/site.example.json to site.json: business hours, rooms, cameras, register, and the zones drawn on each camera's snapshot.
  5. Put the RTSP addresses in the vision worker's cameras.json; start core, then the worker. Open http://<box>:8080 on the office tablet.
  6. Post camera notices at the entrance and staff areas; get each employee's signed acknowledgment.
  7. Run 30 days in SHADOW and mark every flag; check accuracy with tools/eval; then switch alerts on rule by rule.
